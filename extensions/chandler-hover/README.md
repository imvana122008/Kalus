# Цены Chandler в логах Arizona RP

Расширение показывает цену продажи, скупки и медиану по серверам при наведении на **название предмета** в `arizonarp.logsparser.info`. Оно обращается к Wiki только после наведения, хранит найденные цены локально 30 минут и не отправляет их на наш сайт.

При наведении именно на **количество BTC** в записи лога расширение берёт её дату и время (МСК), загружает часовую историческую котировку BTC/USD с CoinGecko или Coinbase и рассчитывает примерную стоимость в игровых долларах: количество × курс. Комиссия внутриигрового банка не учитывается; котировка реальной биржи может немного отличаться от игровой. Загрузка и обновление курса отображаются в подсказке. Успешные часовые котировки хранятся локально 24 часа и повторно проверяются при наведении после истечения этого срока. Если котировка недоступна, сумма не выдумывается.

В логах запятая в `694,409 BTC` разделяет тысячи: это 694 409 BTC. Числа вроде `0,5 BTC` остаются дробными. Версия 1.0.3 ошибочно считала 694,409 как 694.409 BTC и занижала результат в тысячу раз; исправлено в 1.0.4.

## Цены Arizona Market (версия 1.0.7)

Расширение показывает **архивные средние Arizona Market по объявлениям первыми**, даже если Wiki тоже ответила. Для сравнения цены Wiki помещаются в отдельную секцию. Публичные файлы `FREYM1337/forumnick` содержат каталог `ArzMarketV3/items.json` для сопоставления ID с названием; `info_users_buy_chandler.json` и `info_users_sell_chandler.json` дают средние цены скупки и продажи Chandler в игровых долларах, файлы с `_vc` — отдельные средние в VC по серверам. Рядом с каждой суммой указана дата записи. Это не текущая цена и не фактическая завершённая сделка. Для ID 1766 в исходных архивах есть обе суммы; собранный резерв содержит более 4 000 ID с хотя бы одной ценой.

Расширение проверяет исходные файлы при запуске браузера и каждые 30 минут, пока браузер работает, даже без наведения. Если файлы не менялись, оно сравнивает HTTP ETag и не скачивает архив повторно. После сетевого сбоя повторяет попытку при следующем сигнале таймера или наведении (не раньше чем через 5 минут). Подсказка отдельно показывает **дату цены** из ArzMarket и **последнюю успешную проверку источника** по времени браузера. Дата проверки не означает, что источник выложил новую цену. Для цены Wiki отображается время её последней успешной загрузки, а дата самой цены не заявляется. В переданном архиве MoonLoader все четыре файла средних цен заканчиваются 23.09.2026; за 26.09.2026 записей нет. API `api.arz.market/api/getMarketplace` и `r-api.arz.market/api/getMarketplace` во время проверки отвечали 404 на GET и POST, а `arz-market.vercel.app/api/getArizonaMarkets` — 402, поэтому они не используются как источник якобы живой цены.

Сайт цен показывает рабочий экран браузеру с установленным расширением. Это проверка наличия расширения в браузере, а не защита секретных данных: исходный код расширения и сетевые запросы доступны технически подготовленному пользователю.

## Уведомления и обновления кода

При открытии сайта логов расширение загружает текст изменений из собственного комплекта и проверяет последнюю опубликованную запись `extensions/chandler-hover/release-notes.json` на GitHub. Появляется карточка с иконкой, версиями и списком изменений; после «Понятно» она не повторяется для той же установленной версии. Если на GitHub уже есть более новая версия, распакованное расширение показывает ссылку на ZIP сайта. Произвольный JavaScript из сети не загружается и не запускается.

Автоустановка обновлений кода доступна после публикации расширения в Chrome Web Store и установки пользователями именно версии из магазина. Распакованную ZIP-версию Chrome самостоятельно не заменит; для неё нужно скачать новый архив и нажать «Обновить» в `chrome://extensions`. Публикация в Web Store подготовлена в GitHub Actions: она запускается после настройки ID магазина и OAuth-данных в репозитории. Задача публикации теперь упаковывает все необходимые JS, архив цен и доступ к сайту.

## Проверка до публикации

1. Распакуйте ZIP в постоянную папку.
2. В Chrome откройте `chrome://extensions`, включите «Режим разработчика» и нажмите «Загрузить распакованное расширение».
3. Выберите папку с `manifest.json`. Отключите прежний скрипт Tampermonkey, чтобы карточки не дублировались.
4. На странице логов наведите курсор именно на название предмета перед `[id: ...]`.

Эта установка нужна для проверки: Chrome не раздаёт обновления распакованной версии всем пользователям.

## Автообновления для всех

Опубликуйте архив расширения как новый объект в Chrome Web Store. Заполните данные магазина и приватности в аккаунте разработчика. Пользователи устанавливают **именно опубликованное расширение** по ссылке магазина; затем Chrome проверяет новые версии автоматически. Проверка происходит при запуске браузера и каждые несколько часов, а новая версия публикуется после проверки магазином.

Исходники лежат в `extensions/chandler-hover` репозитория `imvana122008/Kalus`. После первой публикации сохраните в настройках этого репозитория:

- Variables: `CWS_PUBLISHER_ID`, `CWS_EXTENSION_ID`.
- Secrets: `CWS_CLIENT_ID`, `CWS_CLIENT_SECRET`, `CWS_REFRESH_TOKEN`.

Создать OAuth-ключи и refresh token можно по официальной инструкции Chrome Web Store API: <https://developer.chrome.com/docs/webstore/using-api/>. Не добавляйте их в исходники. При каждом изменении папки `extensions/chandler-hover` GitHub Actions проверит расширение и после настройки магазина отправит новую версию на публикацию через Web Store API. Номер версии надо увеличить одновременно в `manifest.json` и `release-notes.json`. Если переменные ещё не заданы, пройдут только проверки.

Для новой правки попросите обновить версию в репозитории. Изменение одного лишь ZIP-файла в чате не меняет установленное у пользователей расширение.
