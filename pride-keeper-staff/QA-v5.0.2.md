# PRIDE KEEPER Helper v5.0.2 — проверка

Дата: 11.10.2026. База: опубликованная v5.0.1, commit e2a71c0641f2250190272eac749208709f37cd9a.

## Результат

Состав открывается непосредственно во вкладке Helper: одно окно, одна прокрутка, рабочая область на всю ширину. Тема определяется по структуре первого поста, а не номерам 1623/1646. Для каждой темы отдельно сохраняются люди, изменения, статус и код. Новые ответы для сохранения состава не создаются.

Главный модератор и заместитель — отдельные должности. Точная исходная подпись, включая сокращения и пользовательские должности, сохраняется при редактировании. Имена людей не зашиты в правила расширения: должность выбирается в карточке. В симуляции Shakes_Suicide остаётся главным, а ошибочная подпись Issa_Defender исправляется на заместителя и попадает в сохранённый код.

## Причины и исправления

- Список должностей содержал названия разделов. Неизвестная точная должность заменялась значением по умолчанию. Теперь исходное значение сохраняется, добавлены точные должности, название раздела отделено от должности.
- Вкладка вкладывала старый диалог STAFF в диалог Helper с высотой 620 px, рамкой и собственной прокруткой. Теперь это обычная область с навигацией «Состав / Код поста / Резервная копия / Настройки».
- Глобальные стили страницы сжимали `main.pkfa-screen` до 47% доступной ширины. Внешние margin/max-width сброшены в пределах Helper. Имена и подписи переносятся на узком экране.
- Старые ограничения на номера тем заменены проверкой структуры первого поста: минимум два известных раздела с контейнерами карточек. Иконки в обычной теме или составе в ответе не дают права переписывать первый пост.
- Данные и кэш разделены по thread ID, задания публикации — по post ID. Проверяются origin и тема возврата. Сохраняется только точный существующий первый пост; поздние страницы и Quick Reply исключены.
- Записи людей изменяют актуальное состояние внутри очереди, а не старый снимок. Web Locks сериализуют обновления между вкладками, когда браузер предоставляет API. Без него сохраняется очередь внутри вкладки.
- Предпросмотр аватара больше не обращается к закрытой форме; устаревший результат не заменяет новый. Завершение загрузки кода/настроек не заменяет экран после перехода. Кнопки блокируются на время сохранения.
- Явная кнопка сохранения работает при выключенной автоматической публикации. Включение настройки само не публикует пост.
- Отмена черновика сбрасывает только несохранённую форму: чужие сохранения не заменяются старым снимком. После смены ID прежний ID можно добавить заново, и обе карточки входят в код. «Сохранить и закрыть» закрывает Helper после успешной записи.
- Публикация имеет UUID владельца и общую блокировку записи/обработки задания. Снимок состава проверяется перед созданием задания и перед Save; устаревший код не отправляется.
- Локальный Inter Variable с лицензией SIL OFL сохранён. Проверяется фактическая загрузка шрифта в браузере.

## Браузерный стенд

Запускается настоящий Chromium с реальными файлами расширения и имитацией `chrome.storage`. Карточка взята из разметки, ранее считанной в теме 1646 (пост 4561); окружение страницы, тестовые имена/ID, аватары и сервер синтетические. Это локальная симуляция, а не полная свежая копия форума.

Проверены 14 POST-сохранений существующего поста с последующим чтением обновлённой страницы: исправление должности, добавление с профилем/VK, удаление, добавление/удаление в каждом из пяти разделов и ручное сохранение при выключенном автоматическом. Новых ответов — 0. HTML разработчиков сохранён. Проверены две разные темы и одновременные записи из двух вкладок, включая одновременное добавление людей в одну тему. Ошибок JavaScript — 0.

Ширины 1440, 768 и 360 px: нет горизонтального переполнения, внутреннего диалога, рамки окна и отдельной прокрутки. Проверена мобильная форма человека. Снимки и `report.json` сохраняются в артефакт GitHub Action `pride-keeper-forum-ui-qa`.

Стенд использует отдельный временный профиль. Все сетевые запросы за пределы собственного localhost блокируются. Реальные форумные люди, посты, роли и ответы не изменялись.

## Сборка

GitHub Action проверяет синтаксис JS/CJS, основные тесты, DOM, браузерный стенд и manifest resources **до** ZIP и latest. Тесты и симуляция не входят в установочный архив. Версии manifest/bootstrap/staff/update согласованы: 5.0.2.

После Action проверяются опубликованный latest/tag, его commit, контрольная сумма скачанного архива и содержимое относительно проверенных исходников.

## Границы проверки

Реальная установка в пользовательский Chrome и серверное сохранение на forum.pridekeeper.tech в этом запуске не проверены. Компонент подключённого браузера не загрузился из-за отсутствующего файла, а прямое чтение форума не прошло TLS; локальный стенд позволил завершить браузерные проверки без реальных публикаций. Результат стенда не выдаётся за сохранение на живом форуме.
